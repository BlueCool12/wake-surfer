## 1. 새 작업 세션의 시작점

이 문서는 이전 대화 없이 다음 에이전트가 구현할 수 있도록 작성한 독립적인 실행 스펙이다.
사용자가 이 문서를 지정하여 구현을 요청하면 아래 확정 사항을 작업 요구사항으로 사용한다.
기존 대화의 조사 보고서나 플랜을 별도로 찾아 읽을 필요는 없다.

구현을 시작할 때 다음을 확인한다.

1. 저장소 루트의 `AGENTS.md`, `AGENTS.override.md`, `apps/web/AGENTS.md`와 실제 수정 대상의 하위 지침을 읽는다.
2. 현재 브랜치·HEAD·작업 트리를 확인한다. 기준 커밋과 다르더라도 되돌리지 않고 현재 변경을 파악한다.
3. 아래 파일에서 현재 구현이 이 문서의 조사 기준과 같은지 확인한다.
4. 필요한 변경을 기능 단계별로 진행한다. 관련 호출부를 함께 연결하고 단계별 결과를 보고한다.

조사 당시 기준은 `487a98f`에서 분기한 브랜치의 미커밋 상태였다. 문서 작성 직전에 그 변경이
`9e94ad9`에 커밋된 것을 확인했다. 따라서 과거 조사에서 언급한 “미커밋 변경이 있어야 한다”는
조건은 더 이상 적용하지 않는다. 문서 생성 전 작업 트리는 깨끗했다.

### 사용자 승인과 제한

이번 스펙 구현에 한하여 사용자가 다음을 명시적으로 선택했다.

- 기능 단계별 여러 파일의 생성·수정·삭제를 허용한다. 기본 “한 턴 한 파일” 제한을 적용하지 않는다.
- 메시지 행동 객체 설계와 데이터별 최소 구독 API 변경을 포함한다.
- 새 테스트 코드는 작성하지 않는다.
- 빌드는 실행하지 않는다. 린트·서식·산출물 없는 타입 검사와 실행 가능한 화면 확인으로 검증한다.
- 배포, 서버 계약 변경, TanStack Query 도입은 하지 않는다.
- 현재 작업과 무관한 변경을 되돌리거나 덮어쓰지 않는다.

이 문서는 파일 시스템 권한을 부여하는 수단은 아니다. 실행 환경의 권한은 별도로 따른다.
GitHub 이슈·브랜치·worktree·PR 작업이 필요하면 `github-issue-pr-workflow` 스킬을 사용한다.
기존 #100 작업과 연결하며, 이 스펙만으로 새 이슈·PR·배포를 임의로 만들지 않는다.

## 2. 목표와 설계 원칙

목표는 다음 세 가지다.

1. 데이터 소유자가 생명주기와 상태 변경 규칙을 함께 책임진다.
2. 각 화면이 실제 사용하는 데이터만 구독한다.
3. View가 성립하는 입력 계약과, 계약 안에서 가능한 빈 상태·선택 정보를 구분한다.

### 순수성과 View 책임

- React가 렌더링 함수를 실행하는 동안에는 화면을 계산한다. 전송·상태 변경·DOM 조작을 실행하지 않는다.
- 콜백을 props나 이벤트 속성의 값으로 전달하는 것은 그 콜백을 즉시 실행하는 것과 다르다.
- View 전체를 부수 효과가 없는 함수로 강제하지 않는다.
- 입력 해석, 포커스·커서·높이·스크롤 측정과 실행, 메뉴 열림, 사용자 확인창은 화면 수명에 맞춰 내부에 둘 수 있다.
- 메시지 전송·수락·실패·재전송·폐기·수정·삭제의 상태와 규칙은 메시지·세션이 소유한다.
- 메시지 상태를 CSS·시각·안내 문구로 바꾸는 표현 변환은 View에 둔다.

### props 판단 기준

필수 데이터라고 해서 반드시 props로 주입해야 하는 것은 아니다.
각 값과 함수는 다음 중 하나로 분류한 뒤 경계를 정한다.

| 성격 | 기본 배치 |
| --- | --- |
| 해당 UI 기능과 같은 수명을 갖는 초안·메뉴 상태 | 기능 내부 소유 |
| 기능이 관찰하는 외부 메시지·조회 상태 | 연결부에서 필요한 범위 직접 구독 |
| 외부 동작을 요청하는 표시 View | 연결부가 데이터·가능한 동작 콜백 주입 |
| 이미 가진 입력으로 계산 가능한 표시값 | 사용하는 View 또는 해당 UI 기능 내부 계산 |
| 여러 영역의 배치·선택을 함께 바꾸는 요청 | 공통 소유자와 명시적인 콜백 연결 |
| 명령만 필요하고 데이터를 읽지 않는 기능 | 구독 없는 명령 접근 |

props 개수나 콜백 존재 자체를 문제로 취급하지 않는다.
큰 부모의 전체 구독을 유지한 채 훅·파일 이름만 바꾸는 것으로 완료하지 않는다.
별도 UI 이벤트 버스나 대규모 UI 모델은 도입하지 않는다.

### 데이터 없음의 계약

- 필수 메시지가 없으면 행 연결부가 말풍선을 만들지 않는다.
- 정상적으로 조회를 마친 빈 목록은 목록 View 안에서 표현한다.
- 조회 전·진행 중·실패는 정상 빈 목록으로 변환하지 않는다.
- 반응 없음, 답글 수 0, 수정 정보 없음, 제공하지 않는 동작은 계약 안의 정상적인 선택 정보다.
- 멤버·메모도 포함한 패널 껍데기는 부모 메시지 없이 성립한다.
- 선택된 스레드 본문은 부모 메시지와 서버 스레드 식별자가 있어야 성립한다.
- 존재하지 않는 기능을 성립시키려고 빈 데이터와 아무 일도 하지 않는 필수 콜백을 조립하지 않는다.

## 3. 확정한 사용자 동작과 데이터 수명

| 대상 | 확정 동작 |
| --- | --- |
| 메인 입력 초안 | 채널을 떠나면 폐기. 다른 채널이나 재진입 시 복원하지 않음 |
| 멘션·한글 조합·입력 보조 상태 | 초안과 함께 채널 이탈 시 폐기 |
| 스레드 선택 | 채널 이동 시 미선택으로 초기화 |
| 답글·부모 수정 초안 | 채널 이동, 스레드 닫기, 다른 부모 선택 시 폐기 |
| 같은 스레드의 탭 전환·패널 접기 | 답글·수정 초안 유지 |
| 임시 이모지 반응 | 현재 채널 화면 체류 동안만 유지. 이탈 시 폐기. 서버 저장 없음 |
| 패널 탭·접힘·모바일 열림 | 새 대화 화면의 기본값으로 초기화 |
| 스크롤 위치 | 채널 이탈 시 폐기. 과거 위치 복원 없음 |
| 채팅 세션·메시지 | 기존 actor·target별 레지스트리 수명 유지. UI 제거와 함께 폐기하지 않음 |
| 통화 | 기존 채널 이동·페이지 이탈 시 종료 정책 유지. 이번에는 동작 수정 없음 |

채널 UI 경계에 `channelId` 기반 정체성을 부여하여 재생성한다.
페이지가 소유하는 모바일 채널 목록의 열림 동작은 이번에 추가 변경하지 않는다.
메시지 전송 작업은 UI 수명 밖에서 계속 처리된다.

같은 스레드를 다시 여는 요청은 스레드 탭을 선택한다. 선택 키와 열기 요청은 구분한다.
탭을 바꾸거나 패널을 접어 입력 DOM이 제거돼도 초안은 남아 있어야 한다.
입력 DOM이 다시 생성될 때 높이를 재측정한다. 초안 변화만을 DOM 측정의 유일한 계기로 삼지 않는다.

### 스크롤

- 채널 진입 후 최초 이력이 준비되면 최신 메시지로 한 번만 이동한다.
- 최초 이동은 애니메이션 없이 수행한다.
- 이미 최초 이력이 준비된 세션에 재진입하면 새 목록의 첫 표시에서 한 번 이동한다.
- 준비된 목록이 비어 있어도 최초 처리는 완료된 것으로 기록한다.
- 최초 조회 실패 시에는 완료로 기록하지 않는다. 명시적 재시도 성공 후 처리한다.
- 이후 새 메시지 수신, 내 전송, 재전송, 반응·패널 변경, 이전 기록 조회로 코드가 스크롤을 이동하지 않는다.
- `isAtBottomRef`, `shouldFollowLatest`, 매번 만들어지는 `items`에 반응하는 자동 이동 효과를 제거한다.
- 최초 이동을 위한 기억과 실제 DOM 조작은 목록 View의 수명에 둔다.
- 통화 바의 위치 기준으로 사용하는 목록 DOM 참조는 보존한다.
- 별도의 과거 기록 위치 복원·스크롤 앵커 정책을 추가하지 않는다.

### 조회·전송 상태

가용 메시지가 있으면 최초 조회나 복구 상태와 관계없이 이를 유지하고 필요한 진행·오류 안내를
함께 표시한다. 가용 메시지가 없으면 다음을 구분한다.

| 조건 | 표시 |
| --- | --- |
| 조회 전·최초 조회 중·복구 진행 중 | 진행 상태 |
| 조회·복구 실패 | 실패 안내와 기존 계약상 가능한 재시도 |
| 최초 이력 준비 완료 + 정상 상태 + 빈 목록 | 정상 빈 목록 안내 |
| 선택된 부모 키가 없음 | 스레드 미선택 안내 |
| 선택 키는 있으나 부모 객체·스레드 식별자를 확보하지 못함 | 선택 데이터 부재 안내. 빈 답글 전송 기능을 만들지 않음 |

권한 오류 등 기존에 재시도 동작을 제공하지 않던 상태에 새 재시도 정책을 만들지 않는다.
삭제된 부모 메시지는 부재가 아니다. 기존처럼 삭제 표시와 스레드 접근을 유지한다.

답글에서도 `pending/failed/sent`를 보존하고 실패 시 재전송·폐기를 제공한다.
본문·시각만 남기는 `ThreadReply` 변환으로 전송 상태를 버리지 않는다.
메인 입력과 답글 입력의 기존 Enter·공백 처리 차이는 이번에 통일하지 않는다.

## 4. 메시지 객체와 저장소 계약

### 4.1. ChatMessage

세션이 안정적인 `ChatMessage` 객체를 관리한다. 기존 `OutgoingChatMessage`만의 객체화를 확장해
미확정·전송 완료 메시지가 공통 행동 계약을 갖도록 한다.

객체는 안정적인 `key`, `subscribe/getVersion`, 읽기 전용 메시지 속성과 다음 행동을 제공한다.

```ts
canRetry(): boolean;
retry(): void;
canDiscard(): boolean;
discard(): void;
canEdit(): boolean;
edit(text: string): void;
canDelete(): boolean;
delete(): void;
```

- 읽기 속성은 식별자·본문·생성 시각·발신자/내 메시지 여부·전송 상태·삭제/수정 여부를 포함한다.
- 재전송·폐기는 실패한 미확정 메시지에서만 가능하다.
- 수정·삭제는 현재 사용자의 전송 완료·미삭제 메시지에서만 가능하다.
- 비어 있는 수정 내용 등 기존 실행 시 검사도 유지한다.
- 행동 호출은 현재 상태를 다시 검사한다. 허용되지 않는 요청은 아무 통신도 하지 않는다.
- 실제 통신, 목록 조정, 식별자 연결은 세션에 위임한다.
- 스레드 열기·패널 조작·임시 반응·CSS·표시 문구·시간 형식은 객체의 책임에 넣지 않는다.
- 스레드 열기는 기존처럼 전송 완료 메시지에서 가능하고 삭제된 메시지도 포함한다.
- 서버 수정·삭제 결과 반영 방식은 유지한다. 새 낙관적 수정·삭제나 요청 상태 체계는 추가하지 않는다.
- 폐기되거나 세션이 종료된 객체의 오래된 참조는 다시 전송할 수 없다.

View는 이 객체의 명령을 직접 탐색하지 않는다. 행/본문 연결부가 객체를 구독하고 필요한 표시 데이터와
가능한 행동 콜백을 View에 제공한다. 재전송·수정·삭제 가능 조건을 별도 View에서 재구현하지 않는다.
`messageActionPolicy.ts`에 중복된 객체 행동 조건은 제거하고, 남는 화면 조정 규칙만 해당 기능 가까이에 둔다.

### 4.2. 정체성과 원본

- 로컬 전송 객체 키: `local:${idempotencyKey}`.
- 처음 수신한 서버 객체 키: `server:${messageId}`.
- 객체 생성 이후 키를 바꾸지 않는다.
- 로컬 전송이 수락돼도 처음 만든 객체와 React 항목 키를 유지한다.
- actor·target별 세션에서 서버 식별자와 클라이언트 전송 식별자를 객체에 연결한다.

서버 메시지 원본은 timeline 한 곳에 둔다.

```ts
records: Map<messageId, PublicMessage>; // 서버 메시지 원본
visibleIds: string[];                   // sequence 기준 표시 순서
bufferedBySequence: Map<sequence, messageId>;
```

기존 stream·target·messageId·sequence 검증 인덱스와 cursor 규칙은 유지한다.
보이는 목록·버퍼·메시지 객체마다 서버 본문 사본을 별도 상태로 유지하지 않는다.

수락 전 로컬 객체는 로컬 본문·생성 시각·pending/failed 상태를 소유한다.
수락 후에는 로컬 본문을 별도 진실로 유지하지 않고 serverId로 timeline 원본을 읽는다.
세션의 `byUiKey/byIdempotencyKey/byServerId`는 내용 복사 없이 객체·식별자 인덱스로 둔다.
미확정 또는 아직 timeline 순서에 합류하지 못한 로컬 항목의 순서를 별도로 관리한다.

### 4.3. 수락·실시간 알림 순서

서버 이벤트 계약은 변경하지 않는다. `PublicMessage` 실시간 알림에는 클라이언트 전송 식별자가 없으므로
수락 응답 전 일시적으로 두 행이 보일 수 있다는 제한을 사용자가 허용했다.
본문·시각·발신자 조합으로 추측해서 병합하지 않는다.

| 경우 | 처리 |
| --- | --- |
| 수락 후 실시간 알림 | 수락에서 serverId를 기존 로컬 객체에 연결. 이후 알림으로 새 객체·행을 만들지 않음 |
| 실시간 알림 후 수락 | 별도 서버 객체가 있을 수 있음. 수락에서 로컬 객체를 유지하고 서버 행을 합침 |
| 누락 구간에 있는 메시지 수락 | 로컬 객체를 sent로 바꾸고 계속 표시. gap 해소 시 같은 키로 sequence 위치에 재배치 |
| 실패 후 재전송 | 같은 객체·idempotencyKey를 사용해 pending으로 전환 |
| 중복 수락 | 같은 객체 유지. 실제 변화가 없으면 알리지 않음 |
| 수락 뒤 늦은 거절 | sent를 failed로 되돌리지 않음 |
| 수락 뒤 오래된 재전송 콜백 | 현재 상태 검사로 통신하지 않음 |
| 서버 수정·삭제 뒤 오래된 전송 수락 | 수락 내용으로 최신 서버 원본을 덮어쓰지 않음 |

수락은 다음을 동기 작업으로 묶는다.

1. idempotencyKey로 로컬 객체를 찾는다.
2. 서버 원본을 등록하거나 이미 존재하는 원본을 사용한다. 원본이 있으면 오래된 수락으로 덮어쓰지 않는다.
3. 로컬 객체가 서버 원본을 읽도록 전환하고 sent로 만든다.
4. serverId와 과거 서버 키를 유지되는 객체에 연결한다.
5. 순서를 갱신하고 중복 서버 행을 제거한다.
6. 관련 객체·키 조회·목록 버전을 모두 갱신한 다음 구독자에게 알린다.

수락한 sequence가 현재 cursor 이하이지만 아직 표시되지 않은 경우도 수락 사실을 영구 누락시키지 않는다.
authoritative 수락 원본을 표시 순서에 반영하되 delivery cursor를 임의로 이동하지 않는다.
gap에 있는 수락 객체는 local 순서에 남겨 표시하고, gap이 해소되면 동일 키로 이동한다.

실시간 알림으로 먼저 생긴 서버 객체는 유지되는 로컬 객체로 연결되는 별칭으로 처리한다.

- 오래된 서버 객체 참조의 읽기·가능 여부·명령은 유지되는 객체로 전달한다.
- 기존 구독자도 canonical 객체의 변경을 받을 수 있어야 한다. 별칭 연결 시 변경을 알리고 종료 시 연결을 정리한다.
- 객체 alias에 순환을 만들지 않는다.
- 선택된 스레드 키가 과거 서버 키여도 canonical 키를 해석해 같은 부모를 표시하고 선택 강조를 유지한다.
- 임시 서버 행에만 반응 값이 있으면 유지되는 행으로 옮긴다.
- 양쪽에 임시 반응 값이 있으면 로컬 행 값을 우선하며 합산하지 않는다.
- 모순되는 식별자 연결은 추측 병합하지 않고 기존 프로토콜 오류 경계에서 처리한다.

## 5. 최소 구독과 시작 계약

### 5.1. 공개 읽기 범위

구독 범위는 안정적인 `subscribe`, `getVersion`, 읽기 접근을 제공한다.
React snapshot은 객체·배열 사본 대신 숫자 버전을 사용하며 렌더링에서 실제 값을 읽는다.

| 범위 | 읽는 사실 |
| --- | --- |
| `messageKeys` | 순서가 있는 canonical 화면 키 목록 |
| `message(key)` | 해당 키의 객체·존재 여부·별칭 연결 |
| `ChatMessage` | 해당 메시지의 본문·상태·식별자·행동 가능 여부 |
| `recovery` | 유한한 복구 단계 |
| `olderHistory` | 이전 조회 진행·실패·추가 기록 존재 여부 |
| `initialHistory` | 최초 이력 준비 완료 여부 |

최초 준비 여부는 최초 bootstrap이 정상 준비 상태에 도달하면 참이 되며 재연결 때 거짓으로 되돌리지 않는다.
읽기 범위를 위해 `ChatMessageView[]` 전체를 별도 상태 저장소로 만들지 않는다.

구독 없이 사용하는 세션 명령은 새 메시지 전송·이전 기록 조회·복구 재시도로 분리한다.
기존 공개 API의 사용처를 검색하고, 새 경계로 모두 이전하거나 같은 객체 행동으로 위임한다.
구버전 API를 위해 별도의 데이터 소유자나 규칙을 유지하지 않는다.

### 5.2. 알림 범위

원본 mutation 지점에서 실제 변경 식별자와 조회 상태 변화를 알린다.
매 알림마다 전체 표시 배열을 만들어 이전 배열과 비교하는 방식으로 대체하지 않는다.

| 변경 | 알리는 범위 |
| --- | --- |
| 표시 항목 추가·폐기·순서 변경·중복 행 병합 | 키 목록, 관련 키 조회·객체 |
| 본문 수정·삭제·pending/failed/sent 변경 | 해당 객체 |
| 별칭 연결 | 관련 키 조회와 과거·canonical 객체 구독자 |
| 이전 조회 시작·실패·완료 | 이전 조회 상태 |
| 복구 단계 변경 | 복구 상태 |
| 최초 이력 준비 완료 | 최초 준비 상태 |
| 표시 데이터와 무관한 cursor·throughSequence 변경 | 메시지 화면에 알리지 않음 |

timeline 삽입·교체·버퍼 해제와 세션의 로컬 전송·실패·폐기·수락 모두 이 통지를 거친다.
이미 존재하는 동일 메시지나 동일 상태의 재수신은 불필요한 갱신을 만들지 않는다.
서버 수정 이력처럼 표시 속성에 영향을 주는 별도 자료도 해당 객체의 변경 범위에 포함한다.

원본 여러 곳을 함께 바꾸는 수락·연결 종료 등의 처리는 동기 batch로 묶는다.
모든 관련 원본과 버전을 갱신한 뒤 listener를 실행한다. 중첩 batch를 허용하며 batch 안에 await를 넣지 않는다.
React 자체의 batching만으로 저장소의 원자적 관찰을 보장했다고 간주하지 않는다.

### 5.3. 생성·시작·종료

- 세션은 기존 actor·target 레지스트리에서 얻는다.
- 단건·키 목록·조회 상태 훅은 읽기와 구독만 한다. 각 훅이 연결을 시작하지 않는다.
- 채널 진입 연결부와 선택된 스레드 진입 연결부가 해당 세션의 `ensureStarted()`를 요청한다.
- 세션 단위 최초 시작 기억을 둬 Strict Mode·여러 구독자·재진입이 시작을 반복하지 않게 한다.
- 첫 시작 실패 뒤에도 훅 렌더링으로 자동 재시도하지 않는다. 명시적 복구 재시도와 기존 transport 재연결 절차를 사용한다.
- UI unmount는 구독만 해제한다. 메시지와 세션은 유지한다.
- 세션 dispose에서는 구독·별칭 연결·자원을 정리하고 오래된 객체 행동을 무효화한다.
- 새로운 전역 사용자 상태 모델이나 UI 이벤트 버스는 만들지 않는다.

## 6. 컴포넌트와 props의 최종 책임

### 6.1. 페이지·목록·행

- `ChatChannelPage`는 라우트 해석과 채널 목록 배치를 유지한다.
- `ChannelConversation`은 세션 핸들·채널 UI 상태·기능 사이 연결·배치만 담당한다.
- 부모의 전체 `useChatChannel` 구독과 `messages.find`를 제거한다.
- 목록 연결부는 키 목록, 행 연결부는 안정적인 해당 메시지 객체를 구독한다.
- 선택 부모 연결부는 선택 키의 단건 조회를 사용한다.
- 조회·복구 안내는 해당 상태 범위만 구독한다.
- 목록·행에서 얻은 준비된 데이터와 가능한 콜백을 표시 View에 제공한다.

기존 행이 무관한 변경으로 다시 실행되지 않도록 행 연결부를 메모이제이션하고 props를 안정적으로 유지한다.
선택은 해당 행의 boolean, 임시 반응은 해당 행의 참조만 전달한다.
전체 선택·반응 사전이나 매번 새로 만든 기본 빈 객체를 모든 행에 주입하지 않는다.
선택 변경은 이전·새 선택 행과 패널에, 반응 변경은 해당 반응 영역에만 영향을 주게 한다.

### 6.2. 입력

`ChannelMessageComposer`와 `MessageComposerView`의 상태·이벤트·표시를 하나의 입력 UI 책임으로 합친다.
최종 입력 UI에는 `View` 이름을 사용한다. 기존 표시 파일을 통합 대상으로 사용하고 중복 wrapper는 제거한다.

외부 입력은 다음으로 제한한다.

```ts
placeholder: string;
members: readonly { id: string; name: string }[];
onSend: (text: string) => void;
```

내부에서 초안·멘션 검색·후보 선택·한글 조합·키보드 처리·포커스·커서·높이 측정·공백 여부를 처리한다.
`canSend`는 현재 공백 검사만 포함하므로 내부에서 계산한다.
새 권한·전송 제한을 미리 넣지 않는다.

멘션 선택기는 후보·선택 위치·선택 요청을 받는 하위 View로 유지한다.
입력 기능이 전송 명령 하나를 얻으려고 전체 채팅 세션을 구독하지 않는다.

### 6.3. 스레드

패널 껍데기, 선택된 스레드 연결부, 준비된 본문, 답글 입력·부모 편집을 책임에 맞춰 나눈다.

- 껍데기: 탭·접힘·닫기·배치와 미선택 표시.
- 연결부: 부모 채널 객체 조회, 답글 세션 구독, 표시 상태 선택, 행동 연결.
- 준비된 본문: 필수 부모 데이터와 준비된 답글 상태를 표시.
- 답글 입력·부모 편집: 작성 상태와 DOM 조작. 수명은 3절을 따른다.

부모 수정·삭제는 부모 채널 메시지 객체를 사용한다. 답글 명령으로 부모를 조작하지 않는다.
`parentMessage`와 `isParentDeleted/isParentEdited`를 중복 입력으로 제공하지 않는다.
부모가 없을 때 가짜 `onAddReply`를 만들지 않는다.

멤버 공유 타입을 `ThreadPanelView.tsx`에서 분리해 페이지의 공유 계약으로 둔다.
멘션은 `id/name`만 요구하고 멤버 목록 표현은 `isOnline`을 포함한 타입을 사용한다.
실제 멤버 API나 새 멤버 모델은 만들지 않는다.

### 6.4. 유지할 주입과 내부 책임

| 대상 | 유지·정리 기준 |
| --- | --- |
| 레이아웃의 `ReactNode` 영역 | 완성된 화면을 배치하는 계약 유지 |
| 헤더 이름·열기 콜백 | 라우터나 패널 상태를 헤더 내부로 옮기지 않음 |
| 채널 목록의 식별자·열림·닫기 | 페이지 소유 연결 유지 |
| 목록 DOM 참조 | 통화 바 위치 기준과 공유하므로 외부 주입 유지 |
| 말풍선 메시지·가능한 행동 | 행 연결부에서 주입. View가 세션을 탐색하지 않음 |
| 프레임·메타데이터 | 필요한 표시 입력을 받고 CSS·시간·문구를 내부 계산 |
| 반응 표시 | 값·토글 요청은 외부, 선택기 열림은 내부 |
| 전송 실패 화면 | 장치별 표시 선택·확인창·메뉴 열림은 내부 |
| 복구·이전 조회 화면 | 유한한 상태·명령을 받아 계약 안의 표시를 선택 |
| 읽음 수·멤버 정보 | 현 임시 제공 방식 유지. 실제 조회 기능을 추가하지 않음 |

`messageActionPolicy`의 전송·수정·삭제 조건은 객체 행동과 중복하지 않게 정리한다.
전체 메시지 속성을 화면 상태로 복제하지 않고 연결부 렌더링에서 필요한 표시값을 계산한다.

## 7. 통화 후속 주석

이번에 통화의 모델·구독·화면 동작은 바꾸지 않는다.
다음 세 위치에 원인과 후속 방향을 짧은 주석으로 남긴다.

1. `voiceCallModel.join/leave`: await 중 종료된 참가 시도가 이후 연결·마이크 획득을 이어갈 수 있음.
   후속으로 참가 시도 식별자·취소·늦게 얻은 자원 정리가 필요함.
2. `VoiceCallBarView`의 idle 분기: 모델이 idle+error를 만들지만 바가 사라져 연결 종료 오류가 숨겨짐.
   후속으로 종료·오류 상태 계약과 표시 위치를 정해야 함.
3. `ConnectedVoiceCall`의 children 호출: 단일 모델은 유지되지만 통화 변경마다 대화 전체 JSX가 재구성됨.
   후속으로 모델 생성과 버튼·바의 구독을 분리해야 함.

버튼과 바에서 현재 `useVoiceCall`을 각각 호출하면 모델이 두 개 생기므로 그렇게 변경하지 않는다.
통화 상태 변경에 따른 기존 넓은 재구성은 이번 채팅 최소 구독 완료 기준의 제외 항목이다.

현재 계층을 큰 훅 하나로 옮기거나 DTO 배열을 캐시하는 것만으로 최소 구독을 완료했다고 하지 않는다.

## 9. 검증 방법

### 정적 검사

- 변경 파일만 린트·서식 검사를 수행한다.
- 클라이언트 패키지와 앱의 산출물 없는 타입 검사를 수행한다.
- 새 테스트 파일·스냅샷은 작성하지 않는다.
- 빌드·배포는 실행하지 않는다.
- 단계 완료 후 새 변경·실패가 없으면 같은 검사를 불필요하게 반복하지 않는다.

클라이언트 패키지의 공개 export는 현재 `dist/index.js`, `dist/index.d.ts`를 가리킨다.
오래된 dist로 앱 검사나 화면 확인이 통과한 것을 변경 소스 검증으로 보고하지 않는다.

새 공개 API는 임시 TypeScript 경로 매핑으로 패키지 이름을 변경한 `src/index.ts`에 연결해 검사한다.
개발 화면도 임시 Vite 설정에서 해당 패키지 이름을 변경 소스에 연결한다.
기존 설정을 확장하여 기존 프록시·플러그인을 유지한다.
검증용 경로 매핑은 임시 설정이며, 배포용 export나 저장소 설정을 검증 편의만으로 변경하지 않는다.
서버·브라우저 검증 환경을 사용할 수 없으면 아래 시나리오를 미검증으로 명시한다.
검증 환경을 얻기 위해 임의로 Docker 배포나 빌드를 실행하지 않는다.

DOM 추가·제거·순서 변경에 필요한 목록 갱신은 정상이다.

통화 render-prop의 기존 넓은 재구성은 후속 주석으로 남기며 이번 구독 격리 완료 기준에서 제외한다.

구독 범위는 사용 가능한 프로파일러 또는 임시 계측으로 확인하고 계측은 결과물에 남기지 않는다.
상태·이벤트 순서의 정적 검토와 실제 화면 재현을 구분한다.
환경상 재현하지 못한 순서·서버 동작을 성공했다고 보고하지 않는다.
